  <name>Task 1: Add GLB render-cost stats + triangle-explosion retry loop in worker</name>
  <files>frontend/src/app/features/tools/step-converter/workers/stepConverter.worker.ts</files>
  <action>
Implement post-write geometry accounting and bounded retry-on-explosion.

1. Add a helper that summarizes GLB render-cost from GLB JSON (no BIN decode):

- Count total triangles by summing `accessors[prim.indices].count / 3` across all primitives with indices.
- Count meshes, nodes, nodes-with-mesh, primitives, primitives-with-position.
- Include these stats in an object like `{ triangles, meshCount, nodeCount, primitiveCount, nodesWithMeshCount }`.

2. Define a triangle-explosion policy (Phase 2 allows Claude to choose thresholds):

- Choose a conservative default threshold for “explosion” (e.g. triangles above a few million OR primitives above a high bound).
- Implement `isTriangleExplosion(stats)` returning boolean.

3. Wrap GLB generation with a bounded retry loop:

- Attempt 0: use `message.triangulate` as-is.
- If explosion detected, retry up to 2 times with progressively coarser meshing (increase `linearDeflection`, slightly relax `angularDeflection`).
- Force `relative=false` for retries if it was true (record this in warning detail).
- Keep retries deterministic (no random).

4. Persist results into outputs:

- Add `meshStats` and `conversionWarnings` fields into the `metadata` object written to `${base}.metadata.json` and injected into GLB under `asset.extras.bunlarStepConverter`.
- Add a warning entry for each retry attempt and a final warning if the final output still exceeds the threshold.

5. Writer performance setting parity:

- In the worker’s manual `RWGltf_CafWriter` path (`convertStepDocToGlb()`), set `writer.SetMergeFaces(true)` if available.

Constraints:

- Warnings must be accumulated and surfaced only after conversion completes (no mid-stage ERROR).
- Do not introduce runtime decimation/simplification of GLB buffers; only coarsen OCCT tessellation inputs.
