  <name>Task 1: Add explosion thresholds + bounded retry loop to Explorer worker</name>
  <files>frontend/src/app/features/climate-tech/assembly-viewer/workers/assemblyConverter.worker.ts</files>
  <action>
Implement the missing explosion policy in the Assembly Explorer conversion worker (parity with `stepConverter.worker.ts`).

Gap reason (from verification): Explorer worker converts once, never evaluates explosion thresholds, never retries, and always returns empty `conversionWarnings`.

1. Add pinned thresholds and a single predicate:

- Add a constant object with exact values:
  - `MAX_TRIANGLES = 5_000_000`
  - `MAX_PRIMITIVES = 50_000`
- Implement `isTriangleExplosion(meshStats)` as:
  - `meshStats.triangles > MAX_TRIANGLES || meshStats.primitiveCount > MAX_PRIMITIVES`

2. Force absolute tessellation for every attempt:

- Treat incoming `triangulate` as "requested", but always set `relative: false` when calling `converter.triangulate(...)`.
- If the request had `relative: true`, append a structured warning:
  - `code: 'mesh/relative-forced-false'`
  - `message`: factual (no blame)
  - `detail`: include `triangulateOriginal` and `triangulateForced`.

3. Implement a deterministic, bounded 3-attempt coarsening schedule (attempts 0, 1, 2):

- Define `linearDeflection0 = triangulate.linearDeflection ?? 1` and `angularDeflection0 = triangulate.angularDeflection ?? 0.5`.
- Attempt 0 uses `{ linearDeflection: linearDeflection0, angularDeflection: angularDeflection0, relative: false, parallel: triangulate.parallel }`.
- Attempt 1 uses `{ linearDeflection: linearDeflection0 * 2, angularDeflection: Math.min(1.0, angularDeflection0 * 1.4), relative: false, parallel: triangulate.parallel }`.
- Attempt 2 uses `{ linearDeflection: linearDeflection0 * 4, angularDeflection: Math.min(1.2, angularDeflection0 * 1.8), relative: false, parallel: triangulate.parallel }`.

4. Retry-on-explosion loop (bounded):

- For each attempt:
  - `converter.triangulate(docHandle.get(), triangulateUsed)`
  - `converter.writeBuffer(docHandle, 'glb', { nameFormat: 'productAndInstanceAndOcaf' })`
  - Compute `meshStats` via existing `summarizeGlbGeometry(result.glb)`.
  - If NOT explosion, stop.
  - If explosion and attempt < 2, append a structured warning:
    - `code: 'mesh/triangle-explosion-retry'`
    - `detail` includes `{ attempt, thresholds, meshStats, triangulateUsed }`.
  - If explosion on attempt 2, still return that GLB (do not throw), but append:
    - `code: 'mesh/triangle-explosion-unresolved'` with the same `detail` shape.

5. Ensure the worker output reflects the chosen attempt:

- Do NOT `postMessage` the `model` before the retry loop finishes; only post the final selected GLB.
- Populate `conversionWarnings` with the warnings accumulated during the loop; it must not be hardcoded to `[]`.
- Keep the existing two-phase messaging (`phase: 'model'` then `phase: 'metadata'`) and include `meshStats` + `conversionWarnings` in the metadata phase.

Constraints:

- No new UI in this gap closure.
- No runtime mesh decimation/simplification; mitigation is ONLY via coarser tessellation inputs.
- Keep warning objects JSON-serializable (no Error instances, no typed arrays in `detail`).
