Implementation requirements:

- Detect unsupported content after STEP->GLB write succeeds but before metadata/bounds computation.
  - Use the existing `parseGlbJson()` helper to read glTF JSON from the produced GLB.

  - Update the forced-code catch path to preserve `detail` when present (today it drops detail for forced codes).
- Keep the existing error taxonomy and message protocol stable (`START`/`PROGRESS`/`DONE`/`ERROR`).
- Do not produce any bundle outputs on this failure path.

Gap reason to address: `UNSUPPORTED_STEP_CONTENT` is defined + translated but never emitted.
