  <name>Task 1: Detect empty/unsupported STEP outputs and emit UNSUPPORTED_STEP_CONTENT</name>
  <files>frontend/src/app/features/tools/step-converter/workers/stepConverter.worker.ts</files>
  <action>
Add an explicit “supported container but no supported solids/assemblies” detection and emit a structured worker error with code `UNSUPPORTED_STEP_CONTENT`.

Implementation requirements:

- Detect empty/unsupported content BEFORE attempting STEP->GLB generation.

  - After STEP parsing / node graph creation but before any GLB export call, check whether the returned nodeMap is empty.
  - Treat as unsupported when there are no roots and no nodes (example checks; adapt to actual types):
    - `nodeMap.roots.length === 0` OR `Object.keys(nodeMap.nodes).length === 0`
  - On this path, throw a forced-code error: `__code: 'UNSUPPORTED_STEP_CONTENT'` with `detail` like `{ rootCount, nodeCount }`.

- Detect unsupported content after STEP->GLB write succeeds but before metadata/bounds computation.
  - Use the existing `parseGlbJson()` helper to read glTF JSON from the produced GLB.
  - Treat as unsupported when the GLB has no meshes, or meshes exist but contain no primitives with a POSITION attribute.
  - Include minimal diagnostic `detail` (example: meshCount, primitiveCount, nodesWithMeshCount) so logs are actionable.
- Emit the error as a structured worker error: `{ code: 'UNSUPPORTED_STEP_CONTENT', message, detail? }`.
  - Prefer failing fast: throw an `Error` with `__code: 'UNSUPPORTED_STEP_CONTENT'` and attach `detail`.
  - Update the forced-code catch path to preserve `detail` when present (today it drops detail for forced codes).
- Keep the existing error taxonomy and message protocol stable (`START`/`PROGRESS`/`DONE`/`ERROR`).
- Do not produce any bundle outputs on this failure path.

Optional (non-blocking but recommended):

- Extend `normalizeWorkerError()` to map known "empty model" failures to `UNSUPPORTED_STEP_CONTENT` (e.g. messages containing "no shapes", "empty model"). Do not change precedence for `INVALID_STEP`.

Gap reason to address: `UNSUPPORTED_STEP_CONTENT` is defined + translated but never emitted.
</action>
