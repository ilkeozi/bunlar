<task type="checkpoint:human-verify" gate="blocking">
  <what-built>Browser STEP conversion + bundled outputs</what-built>
  <how-to-verify>
1. Open `http://localhost:5173/tools/step-converter-browser`.
2. Upload `packages/opencascade-convert/src/__tests__/sample/input.step`.
3. Click Convert.
4. Confirm you see stage-based progress text update (parsing/meshing/writing/metadata/packaging).
5. While converting, click Cancel; confirm conversion stops quickly, no download appears, and the file is still selected.
6. Click Convert again; wait for success.
7. Download the `{base}.zip` bundle.
8. Unzip locally and confirm it contains:
   - `{base}.glb`
   - `{base}.metadata.json`
9. Open `{base}.metadata.json` and confirm it includes:
   - `schemaVersion`
    - `assemblyTree` with multiple nodes and meaningful names (not all "UNKNOWN")
    - `nodeMap` with `roots` + `nodes`, and each node has `name` + `childrenIds`
    - `bom` items that include only name + quantity (no instance lists required)
    - `units.outputLengthUnit` is `"m"` and `units.scaleToMeters` is present
    - `boundsMeters` is present and its max dimension is plausibly between `0.05` and `5` meters for this gearbox sample (i.e., not 1000x off)
10. (Optional) Inspect `{base}.glb` with any GLB viewer and confirm the same metadata exists under `asset.extras.bunlarStepConverter`.

11. Invalid STEP error (CONV-05): upload `/tmp/bunlar-invalid.step` and click Convert; confirm:
    - No download appears.
    - UI shows an actionable message.
    - The surfaced error code is `INVALID_STEP` (if code is not shown in UI, confirm in console/log output).
12. Unsupported STEP content error (CONV-05): upload `/tmp/bunlar-empty.step`; confirm error code `UNSUPPORTED_STEP_CONTENT`.
13. Unsupported extension (CONV-05): upload `/tmp/bunlar-not-step.txt`; confirm it is blocked before conversion starts with `UNSUPPORTED_EXTENSION`.
