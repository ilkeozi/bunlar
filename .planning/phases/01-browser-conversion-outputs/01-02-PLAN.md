Update `frontend/src/app/features/tools/step-converter/workers/stepConverter.worker.ts` to:

- Send progress updates as stages (at minimum: `parsing`, `meshing`, `writing`).
- Convert STEP -> GLB (keep existing triangulation options) and return the GLB bytes as a `Uint8Array`/`ArrayBuffer`.
- Do NOT implement metadata generation, GLB `asset.extras` injection, or ZIP bundling in this task. This task ends at a valid GLB.

Worker request/response contract:

- Request includes `fileBytes` and `filename` (used later for bundle naming).
- Progress messages are typed and include `stage` + optional numeric progress.
- Success message returns `{ glbBytes }` (and may include `baseName` computed from `filename`).

Error handling:

- Define a stable error taxonomy (CONV-05) and propagate failures as a single structured error message:
  - `error.code` (stable, machine-usable) + `error.message` (user-facing) + optional `error.detail` (debug-only).

    - `UNSUPPORTED_EXTENSION` (enforced on UI before worker)
    - `INVALID_STEP` (corrupt/non-STEP content)
    - `UNSUPPORTED_STEP_CONTENT` (parses but contains no supported solids/assemblies)
    - `WASM_LOAD_FAILED`
    - `CONVERSION_FAILED`
    - `OUT_OF_MEMORY`
- No partial outputs on error.

<task type="auto">
  <name>Task 2: Implement metadata schema + units sanity + GLB extras injection + ZIP bundle creation</name>
  <files>frontend/src/app/features/tools/step-converter/workers/stepConverter.worker.ts</files>
  <action>
Extend `frontend/src/app/features/tools/step-converter/workers/stepConverter.worker.ts` to produce the Phase 1 bundle output.

Progress stages:

- Add remaining stages and emit them in order: `metadata`, `packaging`.

Metadata schema (Phase 1):

- Always generate assembly metadata for GLB outputs.
- Required top-level fields:
  - `schemaVersion`: string (recommend `"bunlar-step-converter@1"`).
  - `assemblyTree`: a navigable tree of nodes preserving structure + names.
  - `nodeMap`: a normalized map of node ids -> node details.
  - `bom`: simplified list of `{ name, quantity }` (per `01-CONTEXT.md`). Keep `productId`/`kind` if already present, but do not require instance lists.
  - `units`: records STEP length unit + output unit + scale factor to meters.
  - `boundsMeters`: `{ min: [x,y,z], max: [x,y,z] }` in meters.

Assembly structure + names (CONV-02):

- `assemblyTree` must represent the same hierarchy as the OCCT/XCAF assembly (root(s) + children).
- Every node includes a stable `id` and a human-readable `name` propagated from the STEP (no "UNKNOWN" placeholders if a name exists in the source).
- `nodeMap.nodes[id]` includes at least: `{ id, name, parentId?, childrenIds: string[] }`.
- To satisfy the "node map is one-to-one between tree nodes and mesh entries" decision, include linkage from each node to the exported GLB:
  - Add `gltfNodeIndex: number` (and optionally `gltfMeshIndex?: number`) on each `nodeMap.nodes[id]`.
  - Ensure each exported mesh entry maps back to exactly one node id (no duplicates).
- `nodeMap.roots` is a list of root node ids, and must match the roots of `assemblyTree`.

Units/scale + sanity check (CONV-03):

- Read input length units from the STEP/XCAF document when available (record in `units.inputLengthUnit` and `units.inputUnitSource`).
- Ensure GLB output is in meters (glTF standard). Apply conversion using OCCT's coordinate/length conversion (see `01-RESEARCH.md` links: `RWMesh_CoordinateSystemConverter` / `RWGltf_CafWriter`).
- Record `units.outputLengthUnit = "m"` and `units.scaleToMeters` (e.g. `0.001` for mm -> m).
- Compute `boundsMeters` post-conversion.
- Add a sanity check: if `maxDimension(boundsMeters)` is suspiciously tiny/huge for the model AND differs by ~1000x from the unscaled bounds, throw a typed error code `UNITS_SCALE_MISMATCH`.

GLB extras injection:

- Inject the metadata into the GLB using the helper from Plan `01-01` under `gltf.asset.extras.bunlarStepConverter = <metadata>`.
- The sidecar JSON and embedded JSON must be the same object (no divergent fields).

ZIP bundle creation:

- Build a ZIP bundle (in the worker) containing:
  - `{base}.glb`
  - `{base}.metadata.json`
    Where `{base}` comes from the input filename without extension (compute from the request `filename`).
- Return a single success message with:
  - `bundleName` (e.g. `{base}.zip`)
  - `bundleBytes` (ArrayBuffer)

Error codes (extend taxonomy from Task 1):

- Add and use these codes when appropriate:
  - `METADATA_FAILED`
  - `GLB_PATCH_FAILED`
  - `ZIP_FAILED`
- Ensure failures are propagated via the same structured error shape.
- No partial outputs on error.
  </action>

- Accept only `.step,.stp` in `StepConverterForm`.
- In `useStepConverterBrowser`, enforce a hard cap of 15MB on file selection (block before conversion starts).
- If cap violated, do not start conversion; show an actionable error and leave the previous state clean.

Progress + cancel:

- Update worker messaging in `useStepConverterBrowser` to listen for progress stage events.
- Display stage-based status text (update `tools.stepConverter.status.loading` to be stage-aware or add new keys like `tools.stepConverter.status.stage.parsing`, etc.).
- Cancel must:
  - terminate the worker immediately,
  - clear any in-flight state and downloads,
  - keep the file selected so user can retry.

Outputs:

- Replace the current single-file download link (for GLB conversions) with a single bundle download link for `{base}.zip`.
- Do not show separate BOM/node-map download links for the browser flow; the bundle must contain metadata sidecar already.

Actionable errors:

- Update `frontend/src/app/features/tools/step-converter/types.ts` to model failures as `{ code, message }` (and optional `detail` for logging) rather than a free-form string.

- Ensure errors are retryable (no need to reload page) and that cancel does not surface as an error.

Keep the existing Advanced options UI where feasible, but Phase 1 must work in default settings without toggles.
